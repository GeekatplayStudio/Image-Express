### Desktop packaging fix (`b26e4a0`) — the current HEAD

The setup wizard's one-click ComfyUI/Ollama install **could never have worked in a
packaged build**. `/api/runtime/installer/run` spawns `scripts/installers/*.mjs`
relative to `IMAGE_EXPRESS_PROJECT_ROOT`, but electron-builder's file lists excluded
`scripts/` entirely, so it pointed at files that were not in the package. It went
unnoticed because the tested install path (`install.bat`) runs from a source
checkout, where those files exist.

- `package.json`: `extraResources` entry copying `qa-installation.mjs` and
  `installers/**` into `next-standalone/scripts`, filtered so no other dev scripts
  come along.
- `electron/main.js`: ComfyUI now installs to `<userData>/ComfyUI` via a new
  `IMAGE_EXPRESS_COMFY_DIR`. It previously resolved inside `resources/`, which
  electron-builder replaces wholesale on update — a multi-GB checkout would have
  been deleted by every app update.
- `qa-installation.mjs`: honours that override, and skips the `npm build` + jest
  step when running as the packaged app (no source tree, no devDependencies there).
- `verify-package.mjs`: `scripts/` was on the forbidden-entries list; replaced the
  blanket ban with a whitelist that also asserts the installer scripts are present.
- `release.yml`: two latent signing bugs, dormant until secrets are added —
  `APPLE_API_KEY` reaches `notarytool` as `--key <path>` so it must be a **file**,
  not key material; and electron-builder falls back to `CSC_LINK` when
  `WIN_CSC_LINK` is unset, which would have made the Windows job sign `.exe` files
  with the macOS Developer ID cert. Signing env is now scoped per `$RUNNER_OS`.

**Verified on Windows only**: `desktop:verify-package` + `desktop:smoke-package` pass,
and `POST /api/runtime/installer/run` executes the bundled installer end to end
against a real package. A test installer was built at

## Open items — desktop packaging

1. **macOS is unverified.** A `.dmg` cannot be built on Windows (needs `hdiutil` +
   the codesign toolchain), so the fix has never run on macOS. Build it on a Mac
   with Node 24+ and Xcode CLT:

   ```bash
   git clone -b main https://github.com/GeekatplayStudio/Image-Express.git
   cd Image-Express && npm ci
   npm run desktop:dist:mac -- -c.mac.identity=-
   npm run desktop:verify-package && npm run desktop:smoke-package
   ```

   `-c.mac.identity=-` is not optional for an unsigned test build: with no
   certificate electron-builder skips signing entirely rather than falling back to
   ad-hoc, and on Apple Silicon an unsigned Electron app is killed on launch as
   "damaged". The flag forces an ad-hoc signature; the
   `disable-library-validation` entitlement it needs alongside `hardenedRuntime` is
   already in electron-builder's default template. Locally built artifacts carry no
   quarantine flag, so Gatekeeper stays quiet — a *downloaded* CI artifact will
   still need Privacy & Security → "Open Anyway".

   The thing to actually exercise is Settings → Setup Wizard → **Runtime Check** →
   one-click ComfyUI/Ollama install, and confirm ComfyUI lands in
   `~/Library/Application Support/Image Express/ComfyUI`.

2. **Releasing needs a version bump.** `v0.2.0` is already tagged *and pushed*, so
   pushing it again triggers nothing and the artifact names would collide. Use
   `npm version patch && git push --follow-tags`.

3. **Signing credentials are not configured.** The workflow turns signing on purely
   by adding repository secrets — no workflow edit needed. The secret table and the
   procurement caveats (Apple Developer Program required for a Developer ID cert;
   Windows OV/EV keys must now live on a hardware token or HSM, which may make the
   file-based `WIN_CSC_LINK` path unusable) are in [DESKTOP.md](DESKTOP.md#releasing).

4. The `draft-release` job targets a `production-release` GitHub **Environment**
   that must exist in repo settings, and it creates a **draft** — auto-update
   ignores drafts, so nothing reaches users until it is published.
